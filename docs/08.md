

本章汇总 Linux 环境下 RuyiSDK 日常使用、包管理、工具链调用、环境异常 的高频问题。

### 1. 终端提示 `ruyi: command not found`
问题现象

安装完成后，新开终端无法识别`ruyi`命令。

原因

安装程序已写入环境变量，但当前终端未加载更新后的配置。

解决方案
```bash
source ~/.bashrc
```
若使用 zsh：
```bash
source ~/.zshrc
```

### 2. `ruyi update` 成功，但本体版本不变

新手最高频误区

很多用户误以为 `ruyi update` 可以升级 Ruyi 本体。

明确区分

- `ruyi update`：**更新本地工具链索引列表**（刷新可安装的包清单）

- **不升级** ruyi 程序本身版本

- 升级本体需要重新执行安装/升级脚本

### 3. 工具链安装成功，但 `gcc`/`g++` 无法直接调用

问题现象

`ruyi install` 显示安装成功，但终端输入工具链命令提示不存在。

原因

Ruyi 工具链**不注入系统全局环境**，是隔离式环境。

解决方案

必须进入 Ruyi 专属环境调用：
```bash
ruyi shell
```
进入后即可正常使用 `riscv64-gcc` 等工具链。

### 4. `ruyi install` 下载超时、速度慢、安装失败

原因

官方软件源为海外节点，国内网络波动易超时。

解决方案

1. 多次重试安装命令

2. 检查本机网络、代理、防火墙设置

3. 避开网络高峰时段操作

### 5. `ruyi list` 能看到包，但安装提示不存在

原因

本地索引数据库过旧，未同步最新包信息。

解决方案

先更新索引再安装：
```bash
ruyi update
```

### 6. ruyi shell 进入失败 / 工具链版本错乱

排查方案

1. 检查是否真正安装成功：
```bash
ruyi list installed
```
2. 关闭所有旧的 `ruyi shell` 窗口

3. 重新进入环境

### 7. 卸载 Ruyi 提示 `Permission denied`

原因

旧版 Ruyi 安装在系统目录 `/usr/local/bin`，普通用户无删除权限。

解决方案
```bash
sudo ruyi self uninstall -y
```

>新版默认安装至用户目录 ~/.local/bin，无需 sudo。

### 8. 更新/升级 Ruyi 本体后，旧工具链异常

原因

少数跨版本升级会变更本地缓存目录结构。

解决方案

1. 更新索引：`ruyi update`

2. 异常工具链重装即可

---

本章总结

1. **索引更新 ≠ 本体升级**，是新手最大认知误区。

2. 所有 Ruyi 工具链必须在 `ruyi shell` 内使用，不全局生效。

3. 卸载工具链不自动清缓存，空间占用需手动清理。

4. Ruyi 存在系统目录 / 用户目录两种安装模式，权限问题均来自此处。

5. 大部分环境报错，均可通过刷新环境变量、更新索引、重启 Shell 解决。
