# 【Linux RuyiSDK】第 5 集：venv 虚拟环境实战，一个命令切换工具链

---

哈喽，大家好！这集讲 `ruyi venv`。

之前装工具链的时候，路径又长又难记，每次编译都要输一大串。`venv `就是来解决这个问题的，类似于 Python 的` virtualenv`，创建一个隔离环境，激活后工具链直接可用。

---

## 创建虚拟环境

```bash
ruyi venv -t <工具链> -e <模拟器> <配置模板> <目标目录>

举个例子，创建一个通用的 RISC-V 环境:

```bash
ruyi venv -t gnu-upstream -e qemu-user-riscv-upstream generic ./rv-env
```
参数说明：
 -t 
指定工具链
 -e 
指定模拟器（可选）
 generic 
使用通用配置模板
 ./rv-env 
环境存放目录

---

## 激活环境

```bash
. ./rv-env/bin/ruyi-activate
```
激活后，提示符会变成类似 ` «Ruyi rv-env» $  `的样子，说明环境已启用。这时候直接输 ` riscv64-unknown-linux-gnu-gcc  `就能用，不用记长路径了！

---

## 退出环境

```bash
ruyi-deactivate
```

提示符恢复原样，环境退出。

---

## 多工具链管理实战
比如你有两个项目：
 
项目 A 用上游工具链  `gnu-upstream `
 
项目 B 用 PLCT 工具链  `gnu-plct `
分别创建两个环境：
```bash
ruyi venv -t gnu-upstream generic ./project-a-env
ruyi venv -t gnu-plct generic ./project-b-env
```
需要哪个就激活哪个，互不干扰，完美解决版本冲突问题。
