# 【RuyiSDK 包管理器】Linux 篇05：venv 虚拟环境实战，一个命令切换工具链

---

哈喽，大家好！这集讲 `ruyi venv`。

之前装工具链的时候，路径又长又难记，每次编译都要输一大串。`venv `就是来解决这个问题的，类似于 Python 的` virtualenv`，创建一个隔离环境，激活后工具链直接可用。

---

## 创建虚拟环境

```bash
ruyi venv -t <工具链> -e <模拟器> <配置模板> <目标目录>
```

举个例子，创建一个通用的 RISC-V 环境:

```bash
ruyi venv -t gnu-upstream -e qemu-user-riscv-upstream generic ./ruyi-venv
```
参数说明：
-  `-t` 指定工具链，这里用`gnu-upstream`
-  `-e` 指定模拟器，这里用`qemu-user-riscv-upstream
- `generic`  是配置模板
- `./ruyi-venv` 环境存放目录

如果报错说工具没有安装，就先装：
```bash
ruyi install gnu-upstream
ruyi install install qemu-user-riscv-upstream
```
装完再创建就行

---

## 激活环境

```bash
source ./rv-env/bin/ruyi-activate
```
激活后，提示符会变成类似 ` «Ruyi rv-env» $  `的样子，说明环境已启用。这时候直接输 ` riscv64-unknown-linux-gnu-gcc  `就能用，不用记长路径了！
现在验证一下，直接输入工具链名

```bash
riscv64-unknown-linux-gnu-gcc --version
qemu-riscv64 --version
```

---

## 退出环境

```bash
ruyi-deactivate
```

提示符恢复原样，环境退出。

---

## 多工具链管理实战
比如你有两个项目：
 
项目 A 是通用的RISC-V应用，用上游工具链  `gnu-upstream `
 
项目 B 是给玄铁C920核心做优化，需要用带Xthead扩展的工具链
输入：

```bash
mkdir project-b
cd projet-b
ruyi venv -t gnu-plct-xthead generic ./env
```
创建成功后，激活项目b的环境

```bash
source ./env/bin/ruyi-activate
```

验证一下工具链，不同厂商的工具链。gcc的命名前缀是不一样的

```bash
riscv64-plctxthead-linux-gnu-gcc --version
```
如果要回到项目a，先退出
```bash
ruyi-deactvate
```
回到项目a目录重新激活
```bash
cd ../ruyi-venv
source ./bin/ruyi-ctivate
```


