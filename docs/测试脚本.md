# 【测试反馈】 oh-my-ruyi ruyi install.sh 脚本测试
---
## 测试环境
- 操作系统：Ubuntu Linux x86_64
- 测试脚本仓库地址：https://github.com/ruyisdk-test/oh-my-ruyi/blob/master/ruyi-install.sh
- 脚本当前拉取二进制版本：**0.52.0**

## 测试目的
验证 `ruyi-install.sh` 脚本两大核心能力：
1. 本机已存在ruyi时，执行**升级**逻辑
2. 卸载ruyi之后，执行**全新安装**逻辑

## 测试步骤与结果

### 场景一：已有ruyi环境，脚本升级测试

1. 查看本机原有ruyi版本，记录旧版本；
2. 将脚本下载至本地：
```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/ruyisdk-test/oh-my-ruyi/master/ruyi-install.sh -o ruyi-install.sh
```
<img width="952" height="367" alt="dc704dc1cf86127610264eb42222f4a6" src="https://github.com/user-attachments/assets/c30b380c-db95-4cdc-981d-6d2f4d29fe85" />

3.执行本地脚本完成升级：
```bash
sh ruyi-install.sh
```
4.脚本识别本地已存在`ruyi`，自动进入升级流程，下载并覆盖旧版二进制文件；

5.升级完成后查看版本：`ruyi version` ,输出版本为**0.52.0**；

6.执行`ruyi update`，包索引更新正常，基础功能无异常。

### 场景二：卸载ruyi后，脚本全新安装测试
> 注意：本机旧版ruyi安装在系统目录 `/usr/local/bin`，普通用户直接卸载会触发 `PermissionError: Permission denied` 权限报错

1.使用sudo执行ruyi本体卸载：
```bash
sudo ruyi self uninstall -y
```
2.验证卸载结果：`which ruyi`，无输出，确认ruyi程序已移除；

3.使用同一脚本执行全新安装：
```bash
sh ruyi-install.sh
```
4.脚本检测不到ruyi，自动进入全新安装逻辑，将ruyi安装到用户目录`~/.local/bin`；
<img width="788" height="335" alt="e0674ef84a73e0bbe1e01f912e5bf998" src="https://github.com/user-attachments/assets/53be7a4c-0e5b-45f7-95ab-ed40e9a4ae08" />

5.安装完成验证：`ruyi version` ,输出版本为**0.52.0**；

6.执行`ruyi update`，包索引更新正常，基础功能无异常。

---

## 总体测试总结

- 1. 脚本升级、全新安装两大核心功能均工作正常；

- 2. 脚本默认安装至用户目录 ~/.local/bin，不需要管理员权限；

- 3. 旧ruyi如果安装在系统目录，卸载操作需要sudo权限；
